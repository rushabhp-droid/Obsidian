## 1. What Obsidian is

A 24-hour hackathon project. **One threat-rule engine shared by every channel:** email (Gmail), messaging
(SMS/WhatsApp on Android) and network traffic (a Rust daemon on Linux), for consumers (B2C) and
organizations (B2B).

The core demo is the **crowd-immunity loop**: someone reports a malicious link (on the phone, in the web
dashboard, or Gmail flags it) → `RuleService` saves a `threat_rules` row → Redis pub/sub → the web dashboard
updates live **and** every Linux daemon in the org adds an iptables / `/etc/hosts` block → `curl` to that
host fails on the laptop. A bypass reverses it.

**The hour 8 milestone** (gate for all [P1] work): add a domain in the web editor → daemon blocks `curl`;
report from the phone → same block; bypass → `curl` works again. It passes in daemon `--dry-run` mode but
has **not yet been run as root with real iptables**, and the phone half needs a working Android app.

### Scope tags (most important rule)
- **[P0]**: build it, the demo depends on it.
- **[P1]**: only after the hour 8 milestone. Exception: **Code Guard** was built early at the user's request.
- **[ROADMAP]**: never build, not even stubs. Examples: Windows/macOS daemon, Android DNS/VPN, device
  posture, fleet management, Workspace-wide scanning, Cloudflare WAF, Gmail push, Semgrep, Syft/Grype.

When a request touches a [P1] or [ROADMAP] item, name the tag before you implement anything.

## 4. How to build, run and test

```sh
scripts/build.sh                    # test + package backend jar, daemon binary, dashboard into dist/ (--help)
scripts/build.sh run                # dev: bootTestRun (embedded PG/Redis + seed) + dashboard + dry-run daemon
scripts/build.sh run --prod         # docker compose PG/Redis, rebuilds stale artifacts, release daemon
scripts/build.sh demo               # generate official demo accounts + data into demo/ (gitignored)
scripts/build.sh run --demo         # run with the generated demo data (combine with --prod)
#   other run flags: --no-daemon, --daemon-root (real iptables via sudo), --agent-token FILE
#   logs in .run/*.log, Ctrl+C stops everything (daemon first so it cleans up)

cd backend-spring && ./gradlew test        # 256 tests, no Docker
cd backend-spring && ./gradlew bootTestRun # :8080 with embedded PG/Redis + scripts/seed.sql
cd backend-spring && ./gradlew bootRun     # :8080 against docker compose
cd web-dashboard && npm run dev            # :3000 (NEXT_PUBLIC_API_MODE=live to use Spring)
cd daemon-rust && cargo test && cargo build --release
sudo ./daemon-rust/target/release/daemon-rust --server ws://localhost:8080/ws/firewall --token-file /etc/obsidian/agent.token
```

- `build.sh run` does **not** sign in over HTTP to set things up. Spring's `StartupBootstrap` does it
  in-process at startup, controlled by `obsidian.bootstrap.rules` (a rules JSON applied through
  `RuleService` as each named account), `obsidian.bootstrap.agent-token-file`, `agent-admin` and
  `agent-hostname`. It writes the daemon token file (0600) and replaces it if the server no longer knows
  it. This is why it works with a real Turnstile secret, which blocks scripted logins by design.
- Dev accounts (from `scripts/seed.sql`) use the committed password `obsidian-demo-2026`. The official demo
  uses random passwords in `demo/CREDENTIALS.md`; never put those in the repo.
- Gradle's test task declares files outside the project as inputs (`db/init.sql`, `scripts/seed.sql`,
  `docker-compose.yml`, `.env.example`, `web-dashboard/src/lib/types.ts`), so editing them reruns tests.

### Configuration (`.env` at repo root; see `.env.example` for every key)
`PUBLIC_BASE_URL`, `RP_ID`, `POSTGRES_*`, `DB_URL`, `REDIS_HOST/PORT`, `APP_ENC_KEY`, `VT_API_KEY`,
`TURNSTILE_SITE_KEY/SECRET_KEY`, `GMAIL_CLIENT_ID/SECRET`, `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY_PATH`,
`GITHUB_WEBHOOK_SECRET`, `CODEGUARD_ORG_ADMIN_EMAIL`. Every key may be blank locally, and each blank
degrades safely: no VT key → `PENDING`, no Turnstile secret → not checked (warning logged), no Gmail
client → Settings explains it, no Code Guard keys → webhook returns 503. Spring imports `.env` from the
current or parent directory. Format: `KEY=value`, no quotes, no inline comments, no `$(...)`.
Never print `.env` values in logs or chat.

## 5. Architecture and data flow

### Request routing
One hostname. `/api`, `/ws`, `/webauthn`, `/login/webauthn`, `/oauth2`, `/login/oauth2` → Spring `:8080`;
everything else → Next.js `:3000`. `next.config.ts` mirrors the same list as rewrites for the localhost
fallback, including the WebSocket upgrade. Spring's default login page is disabled because it collides
with the Next.js `/login`.

### Auth
- **Web:** password (Argon2id, `Argon2PasswordEncoder(16, 32, 1, 19456, 2)`) or passkey (Spring Security's
  built-in `/webauthn/*` and `/login/webauthn`, JDBC `user_entities`/`user_credentials`). Session in Redis,
  cookie `__Host-session` (`Secure; HttpOnly; Path=/; SameSite=Lax`, no `Domain`). SPA CSRF: `XSRF-TOKEN`
  cookie echoed as `X-XSRF-TOKEN`.
- The dashboard marks each tab in browser storage. Closing the last tab causes a fresh tab to call logout;
  reloading in the same tab retains the session. In live mode, `DashboardSessionPresence` also deletes the
  Redis session 25 seconds after the last `/ws/dashboard` connection closes, to allow a reload/reconnect.
  Mock mode uses the same browser markers with a simulated session; it does not authenticate against Spring.
- **Mobile:** `POST /api/v1/auth/login` with `"client": "MOBILE"` returns `{token: "obm_…", expiresAt}`
  (30 days). Only the SHA-256 is stored (Redis `mobile:token:<sha256>`). No CSRF with a bearer token.
- **Daemon:** `POST /api/v1/agents` (admin) returns an `obs_…` token once; `endpoint_agents.token_hash` keeps
  its SHA-256. The daemon sends `Authorization: Bearer` on the `/ws/firewall` handshake.
- **Turnstile** on register and login (body `turnstileToken`; header `CF-Turnstile-Response` on
  `/login/webauthn`). A failed check is `400`.

### Rules
- `RuleService` is the only writer of `threat_rules`. Each mutation: native
  `INSERT … ON CONFLICT (org_id, user_id, indicator_type, indicator_value) DO UPDATE` (constraint is
  `NULLS NOT DISTINCT`) + `audit_logs` row + a `RuleChanged` event that publishes to Redis
  `channel:firewall:events` **after commit**.
- Indicator values are lowercased (`Indicators`). A reported URL does **not** block its domain; to block a
  link on the network, report its domain as `DOMAIN`. Only `IP`/`DOMAIN` rules reach daemons, and only
  org-level and global ones.
- Scope comes from the caller's role (see the table in `docs/protocol.md` → Rules): ADMIN writes org
  `ADMIN_POLICY`; EMPLOYEE report → org `USER_REPORT` (blocks for the whole org), bypass → user
  `USER_BYPASS` with required `ttlMinutes` (403 if the org disallows user bypass); CONSUMER → user scope.
  Non-admins can't override an org `ADMIN_POLICY` rule (409).
- Precedence lives only in `RulePrecedence`: org `ADMIN_POLICY` → unexpired user `WHITELIST` (only if
  `policy_allow_user_bypass`) → user `BLACKLIST` → org `BLACKLIST` → global → VirusTotal/heuristics.
- TTL bypass is only `threat_rules.expires_at`; expired rules are ignored everywhere. `BypassExpiryJob`
  ([P1]) isn't built, so nothing pushes a re-block to daemons when a bypass expires (see §8).

### Scanning
- One endpoint: `POST /api/v1/scan/unified` for every channel; the Gmail worker calls `ScanService`
  in-process. Lookup per indicator: rules (URL, then its host as DOMAIN/IP; email sender, then its domain)
  → Redis `vt:cache:*` (24 h) → VirusTotal v3.
- VT: client-side limiter (4/min, 500/day); unknown URL (404) → submit, then poll (`vt:pending:*`);
  unknown file → `vt:notfound:*`. While waiting or out of quota the verdict is **`PENDING`, never
  `CLEAN`**. Thresholds on `malicious`: 0 clean, 1–2 `SUSPICIOUS`, ≥3 `MALICIOUS`.
- The sender is checked against rules only and appears in `indicators` only when a rule matched.
  WhatsApp display names are not looked up. Saved contact + `text` → 400. Text is never stored.
- Email: `MimeEmailParser` extracts links and attachment SHA-256; `HeaderAuthValidator` parses only the
  **topmost** `Authentication-Results` from `mx.google.com`. "Verified official" needs SPF+DKIM+DMARC pass
  **and** an allowlist (`obsidian.email.official-domains`) or whitelist-rule match; it skips link and
  attachment scanning.

### Real-time
Redis `channel:firewall:events` carries an envelope `{kind: RULE|SCAN|HEARTBEAT|CODE, orgId, userId, event}`.
`RedisPubSubListener` fans it out to:
- `/ws/firewall` (daemons): full `SYNC` on every connect, then `BLOCK`/`BYPASS` for org-level IP/DOMAIN
  changes. Daemon sends `HEARTBEAT` every 10 s.
- `/ws/dashboard` (web, session cookie): rule/scan/heartbeat events for the viewer's scope;
  `CODE_FINDING` only to admins. The server tracks connections per session and expires the session after
  the last one closes and the 25-second reconnect grace period ends.

### Gmail
Manual OAuth (not Spring's oauth2Login): `GET /oauth2/authorization/google` → Google → `/login/oauth2/code/google`.
Refresh token encrypted with `pgp_sym_encrypt(APP_ENC_KEY)`. `GmailPollingWorker` polls connected
accounts, scans each new message, and stores the result in `scanned_emails`. Not configured →
`/settings?gmail=not-configured`; Gmail API disabled in the Google project → `/settings?gmail=api-disabled`.
Google Cloud: consent screen External + Testing, every connecting address added as a test user,
`gmail.readonly` + `gmail.modify`, Web client with redirect `${PUBLIC_BASE_URL}/login/oauth2/code/google`.
Testing-mode refresh tokens expire after 7 days.

### Code Guard [P1] (built early)
GitHub App → `POST /api/v1/webhooks/github`. Verify `X-Hub-Signature-256` (constant-time) **before**
parsing; 503 when not configured, 401 on a bad signature, otherwise 202 and scan on a virtual-thread
executor.
- push / pull_request: app JWT (RS256, PKCS#1 or PKCS#8 PEM) → installation token → zipball (follow the
  redirect **without** the Authorization header) → zip-slip-safe extract with size caps into a fresh temp
  dir (deleted after) → `gitleaks` + `osv-scanner` via `ToolRunner` (`ProcessBuilder` arg list + timeout,
  no shell) → `code_findings` → Check Run (failure on CRITICAL/HIGH, neutral if a tool is missing, ≤50
  annotations).
- release: stream-hash each asset (100 MiB cap) → existing `VirusTotalClient.lookupFile` (same cache,
  limiter and `PENDING` rule).
- Secrets: store rule, `path:line` and a SHA-256 fingerprint only, **never the value**. Never say the bot
  "hides" or "secures" a key: a leaked key is compromised, and the product drives rotation.
- Dashboard `/code` (admins): list findings, "Mark rotated" (`REVOKED`) / "False positive", both audited
  (`CODE_FINDING_STATUS`).

### Schema additions beyond TODO §4 (all in `db/init.sql`)
Spring WebAuthn tables copied verbatim; `users.display_name`, `gmail_address`, `gmail_last_polled_at`;
`scanned_emails`; `code_findings`. Hibernate validates against it, so any entity change needs a matching
`init.sql` change (and `scripts/seed.sql` / `DemoDataGenerator` if they insert that table).

## 6. Design decisions that aren't obvious

- **`InMemoryCreationOptionsRepository`:** Spring's session-backed passkey creation-options repository
  fails with Redis sessions because `PublicKeyCredentialCreationOptions` isn't `Serializable`. Registration
  options live in memory, keyed by session.
- **`PasskeyLoginGuardFilter`:** rotates the session id at `/webauthn/authenticate/options` (fixation) and
  enforces Turnstile on `/login/webauthn`.
- **No URL→domain derivation on report.** Reporting `https://evil.example/x` creates a URL rule only, so a
  user can't accidentally block a shared host. Clients report the domain explicitly when they want a
  network block.
- **Sender only on rule match** in scan responses, so the response doesn't echo a phone number or name
  that nothing flagged.
- **Errors are RFC 7807 `ProblemDetail`** (`ApiExceptionHandler`); the dashboard shows `detail`.
- **`ApiContractTest`** parses `web-dashboard/src/lib/types.ts` and checks each DTO's JSON field names
  against it. If you change a DTO, change `types.ts` and `docs/protocol.md` in the same commit.
- **`EnvExampleTest`** fails if a config key the app reads is missing from `.env.example`.
- **Turnstile test keys** (`1x00000000000000000000AA` / `1x0000000000000000000000000000000AA`) always pass;
  a real key only works on the hostnames listed in Cloudflare.
- **`scripts/build.sh run --prod` always does an incremental rebuild** (an old jar in `dist/` once lacked
  `StartupBootstrap`). The dashboard is rebuilt when sources or baked settings change (marker file
  `obsidian-build-settings`).

### Android app vs. the contract: known mismatches (fix these first when you touch mobile)
Read from `mobile-android/app/src/main/java/com/obsidian/mobile/network/{ApiClient,Models}.kt`:
1. **Probably won't compile:** `ThreatRule.threatCategory` defaults to `ThreatCategory.MALICIOUS`, but the
   `ThreatCategory` enum has only `SAFE, SPAM, PHISHING, MALWARE`. Add `MALICIOUS` (the backend uses it).
2. **Login:** `AuthLoginRequest` lacks `"client": "MOBILE"` (without it the backend treats the call as
   web and returns a session, not a token) and `turnstileToken`. `AuthLoginResponse` expects
   `token, userEmail, orgId, role`, but the backend returns `{token, expiresAt}`, so deserialization fails
   on the missing `role`. Use `GET /api/v1/auth/me` for the profile. Decide how mobile passes Turnstile when
   the server has a secret: a mobile exemption in `AuthService` or a WebView widget; it is not decided.
3. **Scan response:** backend returns `{verdict, category, vtDetections, scanId, indicators[]}`;
   `category` is `null` for CLEAN/PENDING. The app's non-null `category` with default fails on an explicit
   `null` unless the field is nullable (or `coerceInputValues = true`). `indicatorChecked`/`details` don't
   exist (read `indicators`). `BYPASSED` isn't a backend verdict.
4. **`@DELETE /api/v1/rules/{id}`** isn't implemented by the backend. Removing a block is a Bypass
   (`POST /api/v1/rules/bypass`). Don't add a delete endpoint without checking `TODO.md` §6; if you do, it
   must go through `RuleService` (upsert/audit/publish invariants).
5. **Report:** the backend accepts `threatCategory`; the app sends `sender`/`comment` (ignored). To make
   a phone report block on the laptop, report the link's **domain** as `DOMAIN` (the hour 8 milestone).
6. `HttpLoggingInterceptor.Level.BODY` logs bearer tokens and message text. Lower it (or strip
   `Authorization`) outside debug builds; CLAUDE.md requires that saved-contact text never leaves the phone.
7. `baseUrl` is hard-coded to `https://obsidian.example.com`; point it at the tunnel hostname.
8. No Gradle wrapper in `mobile-android/`; run `gradle wrapper` (Gradle 8.x for AGP 8.7) before
   `./gradlew installDebug`.

The Android rules in CLAUDE.md still apply: read `MessagingStyle` `EXTRA_MESSAGES`, dedupe reposts, watch
`com.whatsapp`, `com.whatsapp.w4b` and the default SMS package, URLs only for saved contacts, resolve
WhatsApp display names through `ContactsContract`, never send file hashes, and say "SIM change detection".

## 9. Invariants you must not break (short form; CLAUDE.md has the full list)

- Only `RuleService` writes `threat_rules`; always upsert + audit + publish. Lowercase indicators.
  Precedence only in `RulePrecedence`. TTL only in `expires_at`, never Redis.
- One scan endpoint. `PENDING`, never `CLEAN`, when VT doesn't know yet. Topmost `mx.google.com` header only.
- Passkeys only through Spring's built-in endpoints; no `/api/v1/auth/passkey*`.
- Daemon: validate every value as `IpAddr` or a strict domain before a system call; `Command::new().args()`,
  never a shell; only the `OBSIDIAN` chain; `/etc/hosts` lines `0.0.0.0 <domain> # OBSIDIAN-MANAGED`, atomic
  rename, flush DNS, clean up on exit; reconcile on every SYNC.
- Code Guard: verify the signature before parsing; tools via `ProcessBuilder` arg list + timeout; never
  store/log/display a secret's value; release assets through the existing `VirusTotalClient`.
- Secrets only from env. Never commit `.env`, `.pem`, `client_secret*.json`, cloudflared credentials or
  `demo/`.
- Changing a message shape means updating `docs/protocol.md`, `types.ts`, and every consumer (Spring,
  Rust, Next.js, Android) in one change.
